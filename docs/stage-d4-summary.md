# 階段 D4「天災、野外求生與救援失敗」摘要（請老師確認後才動工）

依工作守則：動工前先給摘要。**沒有任何程式已經改動。** 規格來源：V3 `HANDOFF.md` 第 12.3、12.4、13 節與 V3.2 原型（`~/Projects/first-aid-kingdom-v3-spec/v3.2/src/script.js` 的 `wxEnter`、`wxTick`、`camp`、`riverWater`、`nextDay`）；救災物資見 `AGENTS.md`「災後救災物資發放」與 `docs/chief-dialogue-draft.md`。

## 先更正一件事

D3 報告我說「救援失敗次數」要老師在 Supabase 加政策。**這是錯的**：`fa_failures` 的「老師可讀自己班上學生」政策（`fa_failures_teacher_read`）已在 `supabase/drafts/001_fa_tables.sql` 裡，並且已經套用。所以 D4 做老師端的失敗統計**不需要你動資料庫**。

## 目標

讓學生遇到「做錯會有嚴重後果」的情境時，看到「救援失敗」畫面、正確知識卡，然後回到當天早上重做；並加入天災與野外求生。序章在沒有天災的日子裡玩起來**不變**。

## 內容分五組

| 組 | 內容 | 說明 |
|---|---|---|
| A 天氣引擎 | `S.wx`（今天）、`S.wxNext`（明天預報）、`S.wxHit`（今天各場景已觸發）；早上訊息先預報；畫面 `rain`／`storm`／`fog` 效果 | 見「要決定 1」：天災由誰、怎麼排定 |
| B 天災與野外事件 | 颱風（戶外避難題、雨衣、失溫題、颱風眼）、豪雨山洪（河谷徵兆題、橋封閉）、森林濃霧（迷路題、哨子）、溪邊溺水救援（叫叫伸拋划排序）、野外找溪水（要煮沸） | 對應新知識卡 `typhoon`、`flood`、`lost`、`signal`、`hypothermia`、`cross`、`riverwater` |
| C 營火露營 | 礦坑敲石 30% 掉打火石；打火石＋木材 3 份可露營（體力最多恢復到 70）；第一次考營火位置、每次出發前考熄火 | 知識卡 `campfire`；**含題目，見「要決定 3」** |
| D 救援失敗 | 嚴重錯誤 → 「救援失敗」畫面 → 正確知識卡 → 回當天早上的存檔點 → 扣救援費 100 → 寫入 `fa_failures`；一般錯誤維持「解說後重選」或扣體力、扣金幣 | 框架 B 階段已有 `rescueFail()`，D4 才把情境接上；老師端顯示「全班最常犯的錯」 |
| E 救災物資（村長） | 山洪、地震災後，村長發放乾糧、開水、打火石；救災物資**不能賣**；只開放災後當天與隔天；受背包格數與負重限制 | 村長圖與對話草稿已備（`chief` 分支，**尚未併入**）；文字需審 |

另外接上前面留下的：**停航**（颱風、豪雨預報時船長拒絕出航，`stormy()` 目前固定回傳「否」）、昏倒原因 `exhaust`（體力被事件扣到 0 時的專屬說明）。
