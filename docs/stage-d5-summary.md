# 階段 D5「老師控制」摘要（請老師確認後才動工）

依工作守則：動工前先給摘要。**沒有任何程式已經改動；Supabase 沒有動任何東西**（我只讀了 `hc_classes` 的欄位型別與既有 policy 寫法）。SQL 草稿：`supabase/drafts/002_fa_class_control.sql`，**由老師在 SQL Editor 執行，我不套用**。

## 目標

老師在老師端，**依班級**控制：
1. 章節開放（目前只有第二章）。
2. 功能開關：野外項目（營火、溺水、裝溪水、阿鹿支線）、村長救災物資——也就是 D4 的兩個預設關閉的開關。
3. 發布天災：颱風、豪雨、濃霧，對全班生效。

這樣文字審完後，**你不需要請我改程式、也不用重新部署**，在老師端按一下就開。

## 怎麼運作

| 項目 | 做法 |
|---|---|
| 資料表 | `fa_class_flags`（每班每個功能一列：開或關）、`fa_class_weather`（每次發布天災一列，可取消）。老師只能管自己班（沿用 `hc_classes.teacher_id = auth.uid()`），學生讀寫不到資料表本身 |
| 學生怎麼拿到設定 | 一個函式 `fa_my_class_control()`：依登入的 email 找到學生所在的班，傳回該班的開關和最新一則天災。遊戲在**啟動時**和**每天早上**各讀一次 |
| 優先順序 | 老師端設定 → 沒設定就用程式預設（`chapters/index.json`、`content/weather.json`）。所以**現在已上線的行為不變**：第二章維持開放，其餘維持關閉 |
| 天災 | 老師按「發布颱風」→ 學生遊戲讀到後，排成**自己遊戲的明天**天災（全班同類型，但發生在各自的遊戲日）；每則公告每位學生只套用一次；老師可「取消」，還沒套用的學生就不會遇到 |
| 沒網路／讀不到 | 用上次讀到的設定（存在這台裝置）；從沒讀過就用預設 |
| 老師端畫面 | 老師端進度頁每個班級新增「班級控制」：三個開關＋「發布天災」（三顆按鈕）＋「取消目前發布」；顯示目前狀態與最後更新時間 |

## 關閉章節時（要特別說明）

老師把第二章**關閉**後，該班學生：已經在第二章的存檔**不會損壞**；但再次進入遊戲時，在第二章場景會被送回綠葉谷村莊（沿用 D1 的「存檔場景不存在就回村莊」），世界地圖鈕與爺爺的信不再出現。重新開放後，一切接回原本進度。
