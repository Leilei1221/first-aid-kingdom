# 階段 D1「章節框架」摘要（請老師確認後才動工）

依工作守則：動工前先給摘要。以下是我的建議與要你決定的事；**沒有任何程式已經改動。**

## 目標

讓遊戲能「載入一章」：場景、角色、對話、知識卡、事件各章獨立成檔，用前綴避免撞名；章節預設關閉，之後由老師端開放（D5）。序章玩起來**不變**（51 情境比對 0 差異）。

## 做什麼

1. 新增 `chapters/ch2/`、`chapters/ch3/` 資料夾的載入機制：讀 `chapter.json`，把該章的 scenes／characters／dialogues／cards／events 合併進現有的 `C.*`。序章維持現在的 `content/`，不搬動。
2. 章節開放旗標：D1 先用「預設關閉」的常數；D5 才接老師端與資料庫。學生在關閉的章節入口會看到「這一章還沒開放」。
3. 存檔：預設不新增欄位；需要時放在 `S.ch.<id>`，並在 `migrate()` 補預設值，**舊存檔與雲端存檔不損壞**。
4. 世界地圖／章節入口：序章到第二章的銜接點（暫定城堡章末之後解鎖），細節 D3 決定。
5. 圖片預載：每章各自的 manifest，只預載該章用到的圖；`tools/gen_manifest.py` 擴充支援章節。
6. 寫定稿的「章節資料包格式說明」（草案已在 `docs/chapter-pack-format.md`），讓老師轉給 Co-work。

## 不做

- 不實作第二章內容（D3）、V3 共用系統與救援失敗（D2、D4）、老師控制（D5）。
- 不改任何醫療與知識卡文字。

## 驗收

- 序章 51 情境比對 0 差異（隨機的金礦位置除外）。
- 用一個**假的測試章**（兩個場景、一個 NPC、一個出口）驗證載入、關閉狀態、舊存檔讀取、雲端來回。
- 假測試章不會被帶進正式版。
